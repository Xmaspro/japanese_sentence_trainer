# ⏱️ Phase 1 每日训练方案 — 场景优先版（草案）

> **状态**：方案定稿阶段。口语句库尚未按本方案重写；`phrases_100.md/js` 仍沿用旧版「功能分类」结构。  
> **核心转变**：先细分真实生活场景 → 再为每个场景生成常用口语表达 → 四项练习围绕**同一周焦点场景**联动。  
> **参考语料**：仓库内 [`japanese-daily-dialogue-main/`](../japanese-daily-dialogue-main/)（日本語日常対話コーパス / JDD）— 人工撰写的标准日语多轮日常对话，作为场景句抽取与シャドーイング脚本的首选来源。

---

## 1. 为什么要改

| 旧方案 | 问题 | 新方案 |
|--------|------|--------|
| 按功能分类背句（相槌 / 自我介绍 / 理由说明…） | 「使用场景」列写的是**触发条件**，不是**生活画面**；脑子要先想语法类别，再套句 | 先锁定「我正在便利店结账」「我正在电车里」等**具体画面** |
| 独り言脚本与暗唱句库弱关联 | 四套脚本偏笼统，与当周背的句型对不上 | 同一周内：跟读素材、暗唱 deck、独り言脚本**共用同一场景** |
| 100 句一次性堆满 | 难判断「这周练完能用在哪」 | 每周 1 个主场景 + 约 10 句；8 周覆盖日常生活主干 |

**不变的原则**：每句必须出声；想到画面直接说日语，不经过中文翻译；60 分钟四段结构保留。

---

## 2. 总体结构：两层 + 四周联动

```
┌─────────────────────────────────────────────────────────┐
│  Layer 0：全场景共通（约 20 句，贯穿 8 周）              │
│  相槌 · 听不清 · 确认 · つなぎ — 任何场景都能用          │
└─────────────────────────────────────────────────────────┘
                            ↓ 每周叠加
┌─────────────────────────────────────────────────────────┐
│  Layer 1：当周焦点场景（约 8〜10 句/周）                 │
│  起床 → 通勤 → 便利店 → … 按真实一天的时间线推进         │
└─────────────────────────────────────────────────────────┘
                            ↓ 同日四项练习
   ① シャドーイング   → 该场景的自然对话/独白素材
   ② 暗唱フレーズ     → Layer 0 复习 + 当周场景句
   ③ 実況独り言       → 在同一场景里「实况解说」
   ④ 発音矯正         → 从当周句子里抽难点音
```

## 3. 场景细分（日常生活 · Phase 1 范围）

按**一天时间线 + 高频接触点**切分。每个场景满足：

- **画面感**：闭眼能想象地点、人物、动作  
- **口语密度**：日本人该场景下**每天会说**的短句，而非书面语  
- **可独り言**：一个人也能练（不要求必须有对话对象）

### 3.1 场景一览

| ID | 场景 | 典型画面 | 子情境（生成句库时的 checklist） |
|----|------|----------|----------------------------------|
| S00 | **全场景共通** | 任何对话中 | 相槌、没听清、请重复、确认、附和、转折 |
| S01 | **起床・晨间** | 闹钟、看窗外、洗漱、选衣服 | 天气感想、困、赶时间、今天安排、自我打气 |
| S02 | **通勤・通学** | 等车、上车、看站名、换乘 | 拥挤、到站、还有几分钟、晚点、让座/站位 |
| S03 | **便利店・超市** | 拿商品、结账、要袋子、加热 | 找东西、多少钱、支付、要小票、店員の一声 |
| S04 | **点餐・外食** | 看菜单、点单、等餐、结账 | 推荐、过敏/不要、味道评价、打包、预约席 |
| S05 | **寒暄・闲聊** | 电梯里、打工前后、邻居碰面 | 好久不见、最近怎样、天气、周末计划、告别 |
| S06 | **电话・预约** | 打给店/医院/学校 | 自我介绍、说明来意、约时间、改期、留言 |
| S07 | **家居・房间** | 做饭、打扫、设备故障 | 做饭步骤独白、坏了/没热水、找房东、垃圾分类 |
| S08 | **天气・出行计划** | 查天气、改计划 | 下雨带伞、太热、取消 outdoor、改室内 |
| S09 | **晚间・回顾** | 睡前、回顾一天 | 今天做了什么、累、明天准备、感谢/反省 |

> Phase 1 共 **9 个生活场景 + 1 个共通层**。8 周训练表见 §6（S08 与 S09 合并进 Week 7〜8 强化周）。

## 4. 场景口语表达 — 生成规则

每个场景产出 **8〜10 句**（Layer 1）+ 从 Layer 0 抽 **3〜5 句**复习，合计每周约 **15 句主动新学**。

### 4.1 单句规格（与 Anki / `phrases_100.js` 对齐）

| 字段 | 说明 | 示例（S03 便利店） |
|------|------|-------------------|
| `sceneId` | 场景 ID | `S03_konbini` |
| `scene`（触发画面） | **中文**：具体情境，一张图能说清 | 「结账时想问能不能用信用卡」 |
| `ja` / `kana` | 口语体，优先です/ます | `これ、クレジットカードで払えますか。` |
| `zh` | 自然中文，非字面直译 | 「这个能用信用卡吗？」 |
| `slots` | 可替换〔〕槽位 | 〔商品〕、〔支払い方法〕 |
| `priority` | ⭐〜⭐⭐⭐ | 该场景第一天就要用的 = ⭐⭐⭐ |
| `register` | 口语 / やや丁寧 | 便利店偏「ですます」即可，不必过度敬语 |

### 4.2 每场景 8〜10 句的覆盖公式

生成时按下面 **8 个功能位** 填句，避免堆同义反复：

1. **进入场景** — 描述当下状态（1 句）  
2. **向他人开口** — 问/买/点/预约（2〜3 句）  
3. **回应他人** — 听懂并答（1〜2 句）  
4. **表达感受** — 累、好吃、着急、放心（1 句）  
5. **说明理由** — 因为…所以…（1 句）  
6. **请求调整** — 能不能…/ 请…（1 句）  
7. **收尾** — 谢谢、下次再来、明天见（1 句）  
8. **独り言独白** — 无对话对象也能说（1 句）

### 4.3 质量门槛（生成后自检）

- [ ] 日本人日常真的会说（避免教科书腔、论文体）  
- [ ] 每句能接到**具体画面**，不是「表达同意」这类抽象标签  
- [ ] 至少 30% 含〔〕槽位，方便换成自己的真实情况  
- [ ] 同一场景内句式长度参差（短句 3 语 + 长句 1 个）  
- [ ] 不与 Layer 0 完全重复（共通句只引用，不重复录入场景 deck）

### 4.4 产出物命名（待实施）

```
phase1_training/
  scenes/
    S00_common.md          # Layer 0
    S01_morning.md
    S02_commute.md
    ...
  scenes_manifest.json     # sceneId → 句列表，供 phrases_100.js 重构
  jdd_scene_index.json     # sceneId → [{ topic, dialogue_id }] シャドーイング用
```

### 4.5 从 JDD 抽取口语句（推荐流程）

JDD 单句平均约 **27 字**（中位 24、90 分位 43），长度适合「反射口语」；整段对话 6〜8 轮居多，适合 15 分钟シャドーイング。

**数据格式**（`japanese-daily-dialogue-main/data/topicN.json`）：

```json
{
  "topic_id": 1,
  "topic_name": "Dailylife",
  "dialogue_id": 1,
  "dialogue_length": 7,
  "utterances": [
    { "turn_num": 1, "speaker": "A", "utterance": "おはようございます。今日はとても良いお天気ですね。" }
  ]
}
```

**交互式生成流水线**（已实现：`tools/scene_dialogue_pipeline.js`）：

用户侧提供两条入口，服务端统一走同一 pipeline：

| 入口 | 用法 |
|------|------|
| **典型场景** | UI 九宫格（S01〜S09）或 API `presetId: "S03"` — 见 `tools/scene_presets.js` |
| **自由输入** | 中文描述场景（例：「在罗森买水并加热便当」）— `sceneDescription` 字段 |

流程：

1. `jdd_scene_matcher.js` 从 JDD 检索 Top 5 候选对话（含相槌计数）
2. Gemini 判断贴合度；≥0.45 则基于语料润色，否则实时生成
3. 输出自然多轮对白 + `keyPhrases` + 相槌说明；并可为 AI 对练生成 mission

API：

- `GET /api/scene-presets` — 典型场景列表
- `POST /api/scene-dialogue` — `{ presetId? , sceneDescription? , key, includeMission? }`
- `POST /api/gemini-chat`（`initCustom: true`）— 内部调用同一 pipeline，额外返回 `sceneDialogue`

**离线抽取流水线**（批量建库，待写 `tools/jdd_scene_extract.js`）：

| 步骤 | 做法 |
|------|------|
| 1. 筛对话 | 按 `sceneId` 关键词 / 人工白名单，从 `topic1.json`（必要时 topic3）取 20〜30 段/场景 |
| 2. 抽 utterance | 每段取 2〜4 句：问句、依頼、感想、相槌（优先 speaker 交替的短句） |
| 3. 归功能位 | 对照 §4.2 八功能位归类；缺位则人工补 1 句或换一段对话 |
| 4. 槽位化 | 专有名词（店名、人名、料理名）改为〔〕；例：ガスト →〔レストラン〕 |
| 5. 写触发画面 | 用中文描述「这段对话发生在什么画面」，**不用**「表达同意」类抽象标签 |
| 6. 去重 | 与 Layer 0、其他场景已收录句比对；保留口语更自然的一条 |
| 7. 登记出处 | 每句 metadata：`jddTopic`, `jddDialogueId`, `jddTurn` — 方便回溯整段跟读 |

**示例（S01，源自 topic1 `dialogue_id: 1`）**：

| 功能位 | 画面触发 | 抽出句 | JDD 出处 |
|--------|----------|--------|----------|
| 进入 | 早上见面聊天气 | 今日はとても良いお天気ですね。 | t1 / d1 / turn1 |
| 回应 | 同意并补充 | 雲一つなくとても良い天気です。 | t1 / d1 / turn2 |
| 感受+邀约 | 天热想吃凉的 | お昼ご飯にはさっぱりした物が食べたくなります。 | t1 / d1 / turn4 |
| 邀约 | 顺势约饭 | よかったら一緒に食べに行きませんか。 | t1 / d1 / turn6 |

**许可与用途**（见 JDD `README.md` / `LICENSE`）：

- CC BY-NC-ND 4.0；**仅限研究/个人学习**，不可对外再分发数据集或衍生语料包  
- 个人 Anki / 本仓库内 `scenes/` 摘录 OK；勿将完整抽取库公开发布  
- 论文引用：赤間ら「日本語日常対話コーパスの構築」(ANLP 2023)

## 5. 每日 60 分钟 — 场景联动 Routine

结构不变；**内容源**改为「当周焦点场景」。

```
[15分] ① シャドーイング      — 当周场景素材
[15分] ② 暗唱フレーズ反復    — Layer 0 复习 + 当周场景句
[15分] ③ 実況独り言練習      — 在同一场景里实况解说
[15分] ④ 発音・アクセント矯正 — 从当周句抽难点
```

### ① シャドーイング（15 分）

**速度日程**（不变）：

| 週 | 速度 | YouTube 設定 |
|----|------|--------------|
| Week 1〜2 | 70% | 0.75 |
| Week 3〜4 | 85% | 0.85 |
| Week 5〜6 | 95% | 0.95 |
| Week 7〜8 | 100% | 1.0 |

**素材优先级**：**JDD 当周场景对话（整段跟读）** → YouTube / NHK 补充语速与口音。

| 焦点场景 | JDD 来源 | 补充素材 |
|----------|----------|----------|
| S01 晨间 | topic1 晨间/天气段（如 d1） | NHK for School 短对话 |
| S02 通勤 | topic1 + **topic3** 电车/駅段 | 駅アナウンス、ちびまる子 |
| S03 便利店 | topic1 コンビニ命中段 | 模拟结账短视频 |
| S04 点餐 | topic1 午餐/外食段（命中最多） | 飲食店短剧 |
| S05 寒暄 | topic1 闲聊段 + topic5 少量 | ひょっこりはんてん |
| S06 电话 | topic1/3 予約段 | 自演电话脚本 |
| S07 家居 | topic1 料理・掃除段 | 料理 vlog 独白 |
| S08〜S09 | topic1 天気 + 一日回顾段 | NHK Web Easy |

**15 分钟シャドーイング配 JDD 对话**（每周固定 2〜3 段，记入 `jdd_scene_index.json`）：

1. **通读**（2 分）— 看中文场景摘要，浏览全文  
2. **分轮跟读**（8 分）— A/B 交替，70%→100% 速（按周）  
3. **整段追读**（4 分）— 不暂停，尽量跟上  
4. **自选一句**（1 分）— 选 1 句加入当周暗唱 deck（与 §4.5 抽取句去重）

**步骤**（不变）：纯听 → 逐句跟读 → 跟追 → 每周录音留存。

### ② 暗唱フレーズ反復（15 分）

| 时间 | 内容 |
|------|------|
| 5 分 | **新句** 3〜5 本（当周场景 deck，Anki） |
| 5 分 | **昨日场景句** 出声复习 |
| 5 分 | **Layer 0** 抽 5 本 + 3 天前场景句 |

**Anki 正面（改）**：场景画面（中文）  
例：「在便利店结账，想问能不能刷卡」  
**背面**：日语口语句  
**标签**：`week3`, `S03_konbini`, `priority1`

### ③ 実況独り言（15 分）

**原则**：不另备四套笼统脚本；**直接用 §3 场景子情境作 checklist**，看着清单逐项用日语说出来。

**当周模板结构**（以 S02 通勤为例）：

```
【进入】今、〔駅名〕にいます。電車を待っています。
【观察】ホームは〔混み具合〕です。外は〔天気〕です。
【行动】〔路線〕に乗ります。次は〔駅名〕です。
【感受】少し〔気持ち〕です。
【计划】あと〔分数〕分で着きます。今日は〔予定〕があります。
【收尾】〔场景句8から1つ〕をそのまま口に出す
```

**时长目标**（不变）：

| 週 | 目标 |
|----|------|
| Week 1〜2 | 1 分钟，卡壳也继续 |
| Week 3〜4 | 2 分钟，主动换子情境 |
| Week 5〜6 | 3 分钟，带感受与理由 |
| Week 7〜8 | 5 分钟，串联 2+ 场景回顾一天 |

### ④ 発音・アクセント矯正（15 分）

**Week 别焦点**（不变）：长音・拗音 → 促音・鼻音 → アクセント → 连读与语速。

**新增**：每周从当周 10 句里标 **3 个发音难点**（例：S03 `払えますか` 促音、`温めて` 连读），编入每日 5 分钟セット。

**每日 5 分钟セット**（ウォームアップ・拗音・早口言葉 — 原文档练习内容保留）。

## 8. 实施步骤（下一步）

1. **确认场景表** — S01〜S09 是否覆盖你的真实一天（可增删子情境）  
2. **交互验证** — 在句练室「💬 互动」选典型场景或自由输入，检查 `sceneDialogue` 对白与相槌  
3. **建 JDD 索引** — `tools/jdd_scene_extract.js` 批量输出 `jdd_scene_index.json`（交互 pipeline 已可单场景生成）  
4. **生成 Layer 0** — 从旧 cat1+cat6 **+ JDD 高频相槌** → `scenes/S00_common.md`  
5. **按周生成 Layer 1** — 每周 8〜10 句，覆盖 §4.2 八功能位  
6. **绑定シャドーイング** — 每周 2〜3 个 `dialogue_id` 与暗唱句同源  
7. **同步工具链** — `phrases_100.js`、`week_checklist.md`、`README.md`
